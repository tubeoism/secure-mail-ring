## Goal
The user can bring a ring in from a code pasted in the task pane, or from the email they are reading ("Import from this email", D-15). Either way they first see who made the code, how trustworthy the source is, and exactly what changes, with anything riskier highlighted, and only then confirm. A tampered, expired, foreign or older code is refused with a clear message.

## Allowed paths
- `src/taskpane/import/**` (flow, preview, tests)
- `src/readmode/ui/**` (the read-mode pane that mounts the same flow)

## Inputs (read-only)
- `@smr/core`: `CoreApi.decodeRing`, `CoreApi.diffRings`, `verifyImportSource`, `headerValues`, `splitAddress`, `normalizeAddress`, types `RingDiff`, `ImportSourceCheck`, `CodecError`, `ShareCodePayload`, `Ring`.
- Adapters: `StorageAdapter.loadRings/saveRings`; `OfficeAdapter.getUserAddress`, and in read mode `getReadBody`, `getInternetHeaders` and `getSenderAddress` (added to the contract by CL-05D).
- Fixtures: `buildLiveShareCodes()` and `LIVE_SHARE_CODE_ERRORS` (valid, spaced, quoted, tampered, expired, oversize, foreignKey); `fixtures.rings` for older and newer revisions of a ring.
- i18n keys: `import.*` (including the keys added by CL-05D), `editor.*` labels and `policy.mode.*` for showing settings, `common.*`.

## Requirements
1. **One flow, two sources.** Component `ImportFlow({ core, office, storage, source })` with `source` either `{ kind: "paste" }` or `{ kind: "email" }`. The task pane mounts the paste source (`import.title`, `import.paste`); the read-mode pane mounts the email source and starts without asking for input.
2. **Get the code.** Paste: the text exactly as typed. Email: `office.getReadBody()`. Pass the text unchanged to `core.decodeRing`; do not clean or search it yourself (the codec tolerates spaces, line breaks, quoting marks and surrounding text).
3. **Errors.** Map `CodecError` to keys, one each: `malformed` → `import.error.malformed`, `tampered` → `import.error.tampered`, `expired` → `import.error.expired`, `tooLarge` → `import.error.tooLarge`, `unsupported` → `import.error.unsupported`. No code in an email gives `malformed`. Adapter and storage errors show their own `messageKey`. After an error the user can paste again.
4. **Preview.** After a successful decode show: ring name, `import.issuer` and `import.issuedAt` values (as text), and the diff against the stored ring with the same `id` (`null` if none) from `core.diffRings`.
   - `revRelation` `older`: show `import.older` and offer no confirm button. `same`: show `import.same`, no confirm button. `new` or `newer`: continue.
   - A new ring (`new`): there is nothing to compare, so show **all** its settings (members, subject tag, attachment tokens and exempt extensions, ordering, field rules, internal-domain treatment, first-time check, policy modes), labelled with the `editor.*` and `policy.*` keys, and `import.new`.
   - An update (`newer`): show every non-empty part of the diff: added and removed members, policy changes, `internalDomainChange`, `firstTimeCheckChange`, `ignoreInlineChange`, added and removed field rules, tokens and exempt extensions.
   - Highlight, with colour **and** text (not colour alone): every `loosened` change (`import.diff.loosened`), every added member outside the internal domain (`import.diff.external`; the internal domain is the domain of `getUserAddress()`), and every added rule, token or exemption (`import.diff.added`); removals use `import.diff.removed`.
5. **Source check.** Email source: `verifyImportSource({ senderAddress, internalDomains: [user's domain], authenticationResults: headerValues(headers, "Authentication-Results"), issuer })`. Show `import.verified` when `trusted`, otherwise `import.unverified` plus one line per entry in `warnings` (`import.warning.senderExternal`, `authFailed`, `authUnverified`, `issuerMismatch`). Paste source: show `import.source.pasted`. `trusted` never skips the preview and never confirms by itself.
6. **Confirm.** The `import.confirm` button saves the ring through `storage.saveRings` (replace the ring with the same `id`, or append) and shows `import.done`. The ring is saved exactly as decoded: no edits, no changes to settings, no changes to the global floor. A storage failure shows its message and keeps the preview open. Cancel (`common.cancel`) leaves storage untouched.
7. The decoded ring and every string in it are rendered as text only.
8. Accessible and keyboard-reachable; the preview announces itself (`aria-live`) and the confirm button is not the first focus target.

## Acceptance criteria
- [ ] AC-1 Paste of `valid`, `spaced` and `quoted` codes gives the same preview; confirm saves the fixture ring once (mock storage).
- [ ] AC-2 `tampered`, `expired`, `oversize` and `foreignKey` show the message of `LIVE_SHARE_CODE_ERRORS[name]` mapped as in requirement 3; storage is untouched; the user can paste again.
- [ ] AC-3 A stored ring with revision R and a code with a lower revision shows `import.older` and no confirm button; the same revision shows `import.same`; a higher revision shows the diff.
- [ ] AC-4 New ring: every setting of the ring appears in the preview. Test with a ring that has a field rule, an exempt extension and a non-default policy and assert each is on screen.
- [ ] AC-5 Update diff: one test per diff part (members, policy, internal-domain, first-time check, ignore-inline, field rules, tokens, exempt extensions); a loosened policy and an external added member carry the highlight text.
- [ ] AC-6 Email source with each outcome: trusted (no warnings), external sender, failed DKIM, no `Authentication-Results`, issuer different from sender, and a forged lower header ignored (headers built from the CL-05D fixtures). The lines shown match `warnings` exactly.
- [ ] AC-7 Imported ring in storage equals the decoded ring (`toEqual`); no other key of storage or settings changed; cancel changes nothing.
- [ ] AC-8 Storage failure on confirm keeps the preview and shows the message; a second try works.
- [ ] AC-9 Keyboard walkthrough (Tab, Enter, Esc) and screenshots of paste, error, new-ring preview, update preview with highlights, and email source with warnings, in `vi` and `en`, under `docs/tasks/evidence/AG-11/`.
- [ ] AC-10 `npm run verify` passes; only the allowed paths changed; no new dependency.

## Edge cases
- A code inside a long email thread with several quoted copies: the first complete block is used (core behaviour).
- Two blocks in one email with different content: the first is used; do not offer the second.
- Sender that cannot be read (adapter error or an address `normalizeAddress` rejects): pass an empty sender to `verifyImportSource`, which reports `senderExternal`; show the warning, do not fail the import.
- Ring name or member value that looks like HTML or contains very long text: shown as text, wrapped.
- 500-member ring: the member list is scrollable or paged and the pane stays responsive.

## Out of scope
- Changing the stored global floor or applying policy (the floor is applied when rings are evaluated); fixtures of real tenant headers (CL-01 evidence); import of multiple rings at once; the manifest button itself (CL-06).
