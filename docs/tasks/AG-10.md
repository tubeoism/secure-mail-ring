## Goal
From a saved ring the user gets an encrypted share code, can copy it, and can open a ready-made email to the colleagues of the ring who are in the internal domain, with the code and three steps for importing it. The user reviews the email and sends it themselves.

## Allowed paths
- `src/taskpane/share/**` (component, pure helpers, tests)

The ring editor (AG-03) mounts the component; AG-10 does not edit it.

## Inputs (read-only)
- `@smr/core`: `CoreApi.encodeRing`, `normalizeAddress`, `splitAddress`, types `Ring`, `Member`, `CodecError`.
- Adapters: `OfficeAdapter.getUserAddress()`, `OfficeAdapter.displayNewMessage(draft)`. Pass `core` and `office` as props so tests use `core` and `MockOfficeAdapter` from `src/shared/contracts`.
- Fixtures: `fixtures.rings` (include the 500-member ring and a ring with no address members).
- i18n keys: `share.title`, `share.code`, `share.copy`, `share.email`, `share.blocked.external`, `share.recipients`, `share.recipients.none`, `share.email.subject`, `share.email.body`, `share.error.encode`, `share.error.tooLarge`, `common.copied`.

## Requirements
1. Component `ShareRing({ ring, core, office })`. On mount it calls `core.encodeRing(ring, { issuer: <user address>, issuedAt: <now as ISO 8601> })` and shows the result in a read-only monospace text area labelled with `t("share.code")`. Show a loading state while it runs.
2. Copy button (`share.copy`) writes the code to the clipboard and then shows `common.copied`; if the clipboard is refused, select the text so the user can copy by hand. Never log the code.
3. Recipients for the share email: the `address` members of the ring whose domain equals the domain of the user's address (compare with `normalizeAddress` / `splitAddress`, case-insensitive), without the user's own address and without duplicates. Show them as a checkbox list (`share.recipients`), all ticked. Address members of any other domain are never offered; when there are any, show `share.blocked.external` once. Domain and sub-domain members are not expanded into addresses.
4. "Share with colleagues" (`share.email`) calls `office.displayNewMessage({ to, subject, body })` with `to` = the ticked addresses, `subject` = `t("share.email.subject", { ring: ring.name })`, `body` = `t("share.email.body", { ring: ring.name })`, then a blank line, then the code exactly as `encodeRing` returned it. The button is disabled with no ticked address, and `share.recipients.none` is shown when there is no eligible colleague (the code and Copy still work).
5. Errors are shown through `t()`: `tooLarge` gives `share.error.tooLarge`; every other codec error gives `share.error.encode`; an adapter error shows its own `messageKey`. Nothing is swallowed.
6. Accessible: every control is keyboard-reachable with a visible label; the code area has an accessible name; status changes (copied, error) are announced with `aria-live`.
7. Everything read from the ring is rendered as text (no `innerHTML`).

## Acceptance criteria
- [ ] AC-1 With a fixture ring, the code area shows a block that `core.decodeRing` decodes back to the same ring (test calls `decodeRing` on the displayed value).
- [ ] AC-2 Copy writes exactly the displayed code to the clipboard (mocked) and shows the copied message; with a refused clipboard the text is selected and no error is thrown.
- [ ] AC-3 Recipients: a ring with internal addresses, external addresses, a domain member and the user's own address offers only the internal addresses, once each, case-insensitively; the external note appears. Evidence: test names.
- [ ] AC-4 The draft passed to `displayNewMessage` has `to` equal to the ticked addresses, the translated subject and body, and the code last. Unticking an address removes it from `to`. `MockOfficeAdapter` records one call and no message is sent.
- [ ] AC-5 No eligible recipient: share-email button disabled, `share.recipients.none` shown, code and Copy still available.
- [ ] AC-6 The 500-member fixture ring either produces a code or shows `share.error.tooLarge`, never an exception; a core stub that returns each `CodecError` code shows the mapped message for each.
- [ ] AC-7 Adapter failure from `displayNewMessage` shows its message key text and leaves the dialog usable.
- [ ] AC-8 Keyboard: Tab order reaches code area, Copy, recipient boxes and the share button; Enter and Space activate buttons. Screenshots of loaded, no-recipient and error states in `vi` and `en` under `docs/tasks/evidence/AG-10/`.
- [ ] AC-9 `npm run verify` passes; only the allowed paths changed; no new dependency.

## Edge cases
- Ring name with quotes, angle brackets or very long text: shown and passed as plain text.
- User address with upper-case letters or a plus tag: compared after normalisation; a plus-tagged own address is still "own" only if the normalised addresses are equal.
- The ring is edited after the dialog opened: the code shows the ring passed in; the editor remounts the component.

## Out of scope
- Blocking external recipients inside the Outlook compose window (send-time rule, CL-08); expiry of the code; sending automatically; email addresses outside the ring.
- The organisation's list of internal domains: v1 uses the domain of the user's own address (see CL-05D notes).
