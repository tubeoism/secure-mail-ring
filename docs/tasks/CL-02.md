## Goal
Antigravity can build every task-pane screen in a plain browser against stable types, adapters, fixtures and i18n keys, and the later core cards (CL-03 to CL-05) have fixed signatures to implement. Nothing here depends on Outlook.

## Allowed paths
- `packages/core/src/model/**` (types, schema `smr/1`, validation) and the public export list in `packages/core/src/index.ts`
- `src/shared/contracts/**` (adapter interfaces, mocks, fixtures, i18n key list, README)
- `src/shared/i18n/**` except `locales/**` (the `t()` function and key typing)
- Root config and dev tooling for the browser dev server (see decision D2)
- `docs/tasks/BOARD.md`, `docs/tasks/CL-02.md`

## Inputs (read-only)
- Plan §5.3 data model and §3 requirement tables.
- `docs/tasks/AG-01.md` (the first consumer; its Inputs list defines minimum fixture content).

## Design decisions (lead, reversible until the tag)
- **D1 Types live in `@smr/core`** (`model`), not in `src/shared/contracts`, because core must stay free of app imports (NFR-6). `src/shared/contracts` re-exports them so Antigravity has one import surface.
- **D2 Dev tooling for AG-01:** add React 18, Fluent UI React v9, webpack and webpack-dev-server, and the script `npm run dev:taskpane` (plain browser, no Outlook). AG-01 requires it and Antigravity may not add dependencies. This is the first card that adds product dependencies; list them in the PR.
- **D3 Validation library:** `valibot` (smaller bundle than `zod`; the event handler bundle runs in a size-sensitive JS-only runtime).
- **D4 Stub core:** `@smr/core` exports a `CoreApi` interface (evaluate, sort, diff, encode/decode, suggest ring, lookalike, policy merge). CL-02 ships `stubCore`, a fixture-backed implementation returning canned results, so UI work is not blocked on CL-03 to CL-05. The real implementations keep the same signatures; any signature change after the tag goes through a CCR.

## Requirements
1. **Model:** `Ring`, `Member`, `OrderLists`, `AttachmentRules`, `PolicyMode` (`warn | acknowledge | block`), `PolicyKey` (six violation kinds), `FieldRule`, `GlobalSettings` (policy floor, lookalike exceptions, learning mode, language), `Recipient`, `AttachmentInfo`, `ComposeSnapshot`, `Finding`, `EvaluationResult`, `Mutation`, `ShareCode`. Matches plan §5.3 exactly; schema id `smr/1`.
2. **Validation:** `parseRing`, `parseSettings` (valibot) that reject unknown or malformed input and never throw on untrusted data (return a result type).
3. **`OfficeAdapter`** (the only way app code reaches Office): get/set recipients (To/CC/BCC), subject, attachments (names only), from address, user profile address, session data get/set, custom properties get/set, display new message form, read-mode body text and internet headers, show notification. All methods return `Promise<Result<T, AdapterError>>`; no Office types leak.
4. **`StorageAdapter`:** typed keys for rings, settings, history (Bloom), with `usage()` for the storage meter (bytes used and budget per plan §5.4).
5. **Mocks:** `MockOfficeAdapter` (seeded from a `ComposeSnapshot`, records mutations) and `MockStorageAdapter` (in memory, enforces a configurable quota).
6. **Fixtures** in `src/shared/contracts/fixtures/`: `rings.json` (at least 4 rings incl. a Strict preset, one expired, one with field rules), `settings.json`, `findings.json` (every finding kind and every policy mode), `compose.json` (several snapshots, incl. a lookalike domain and a foreign-ring file token), `sharecodes.json`. All validated by `parseRing`/`parseSettings` in a test.
7. **i18n:** typed `I18nKey` union generated from `i18nKeys.ts`; `t(key, params?)` with `vi` and `en` catalogs loaded from `locales/**`; missing key is a typecheck error. `check:i18n` additionally verifies that every catalog contains exactly the keys in `i18nKeys.ts` (AG-07 fills the values; until then the check reports the gap as a warning, not a failure).
8. **README** `src/shared/contracts/README.md`: import rules for Antigravity, how to run the browser dev server, how to raise a CCR.
9. **Release:** merge, then tag `contract-v1`, BOARD note, move AG-01 dependency to satisfied.

## Acceptance criteria
- [x] AC-1 Model types and schema match plan §5.3; a round-trip test `parseRing(JSON.parse(JSON.stringify(ring)))` passes for every fixture ring.
- [x] AC-2 `parseRing` rejects at least: unknown `schema`, member with bad `kind`, policy value outside the enum, oversize arrays; none of them throws.
- [x] AC-3 `OfficeAdapter` and `StorageAdapter` expose no `Office.*` or DOM type (typecheck of `packages/core` with `lib: ["ES2022"]` only).
- [x] AC-4 `MockOfficeAdapter` passes a contract test suite that the future real adapter (CL-06) must also pass (suite is exported and reusable).
- [x] AC-5 `stubCore` returns a result for each `CoreApi` method using fixtures; a test asserts every `Finding` kind and every `PolicyMode` appears at least once.
- [x] AC-6 `t()` typechecks keys; a deliberate wrong key fails `tsc` in a type test; `check:i18n` reports catalog gaps as designed.
- [x] AC-7 `npm run dev:taskpane` serves a placeholder page in a desktop browser that imports `@smr/core`, the mocks and `t()` and renders fixture ring names (smoke test in CI via a build, not a browser).
- [x] AC-8 Core line coverage stays ≥ 90 %; `npm run verify` green; no secret, domain or address of a real organisation in fixtures (fictional `abccorp.vn`, `partner.vn` only).
- [ ] AC-9 Tag `contract-v1` exists on the merge commit and BOARD has the note.

## Edge cases
- Fixture addresses use only fictional domains; Vietnamese diacritics and a Cyrillic homograph appear in fixtures to exercise later cards.
- A ring at the size limit (many members) exists in fixtures to test the storage meter.
- Adapter errors are values, never thrown; an `AdapterError` carries a code and an i18n key.

## Out of scope
Real matching, ordering, lookalike, Bloom, codec, policy logic (CL-03 to CL-05). Real Office adapter (CL-06). Locale values (AG-07). Any screen (AG cards).
