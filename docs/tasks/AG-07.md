## Goal
Every text key of `contract-v1` has a Vietnamese and an English value, so the task pane, the acknowledge pane and the send-time alerts can show real text instead of key names. After this card `I18N_STRICT=1 npm run check:i18n` passes.

## Allowed paths
- `src/shared/i18n/locales/vi.json`
- `src/shared/i18n/locales/en.json`

(Translation values only. Keys are defined by the contract; adding, renaming or dropping a key is a Contract Change Request.)

## Inputs (read-only)
- `src/shared/contracts/i18nKeys.ts`: the 126 keys, one per line. Groups: `app`, `nav`, `common`, `rings`, `editor` (33), `policy`, `finding`, `compose`, `ack`, `settings`, `share`, `import`, `error`.
- `src/shared/i18n/translator.ts`: `t(key, params)` replaces `{name}` with the parameter value and leaves an unknown `{name}` as it is.
- `scripts/i18n-check.mjs`: the completeness check.
- Placeholders of the finding texts (CL-05 D4):

  | Key | Parameters |
  |---|---|
  | `finding.outsider` | `{address}`, `{field}` (`TO`, `CC` or `BCC`) |
  | `finding.missingToken` | `{file}` |
  | `finding.foreignRingToken` | `{file}`, `{ring}` (names of the other rings, already joined by `, `) |
  | `finding.lookalike` | `{address}`, `{similarTo}` (the trusted domain), `{ring}` (name of the ring it comes from; **empty** when it is the sender's own domain) |
  | `finding.firstTime` | `{address}` |
  | `finding.fieldRule.mustBeIn` | `{address}` or `{pattern}`, `{field}`, and `{foundIn}` when the match sits in another field |
  | `finding.fieldRule.mustNotBeIn` | `{address}`, `{field}` |
  | `finding.fieldRule.onlyIn` | `{address}`, `{field}`, `{foundIn}` |

  Parameters of other keys are not defined by `contract-v1`. Write those texts without values; if a sentence cannot work without one, raise a CCR (`docs/tasks/_CCR_TEMPLATE.md`) and keep going against the rest.

## Requirements
1. `vi.json` and `en.json` each hold exactly the 126 keys of `I18N_KEYS`, in the same order as the list, as a flat JSON object of strings. No other keys, no nesting.
2. Use only the placeholders in the table above, spelled exactly, and use the same set of placeholders in `vi` and `en` for the same key. Never build a sentence by joining separately translated pieces.
3. `finding.lookalike` must read well in both cases: with a ring name and with `{ring}` empty. Plan FR-6.3 gives the model: `abcc0rp.vn` rất giống `abccorp.vn` (ring ALPHA). When `{ring}` is empty the wording may not leave an empty pair of brackets or a dangling word such as "ring".
4. Keep "ring" as the product term in both languages (the plan does the same in Vietnamese). Do not translate "ring" in one place and not in another.
5. Finding texts (`finding.*`) are one line each and are cut to the Smart Alerts limit by the handler. The limit is measured in Spike 7; until it is known, keep each at most 110 characters before substitution in both languages.
6. Text is UTF-8 in Unicode normal form NFC, with no leading or trailing spaces, no line breaks, and no HTML or markup.
7. Tone: short, plain and polite; the same register across the whole catalog. Vietnamese uses "bạn" only where the sentence needs an addressee; prefer imperative or neutral phrasing.
8. Do not edit code, tests, scripts or the key list.

## Acceptance criteria
- [ ] AC-1 `I18N_STRICT=1 npm run check:i18n` passes: both catalogs have the same keys and cover the contract list, with none unknown.
- [ ] AC-2 For each key, the placeholders found in the `vi` text equal those in the `en` text, and every placeholder is allowed by the table above. Evidence: the PR description lists the keys that have placeholders.
- [ ] AC-3 `finding.lookalike` rendered in both languages with `{ring}` = `ALPHA` and with `{ring}` = `` (empty). Evidence: the four rendered lines in the PR description.
- [ ] AC-4 All eight `finding.*` texts rendered with example values, in both languages, none longer than 110 characters. Evidence: a table in the PR description.
- [ ] AC-5 Both files are valid JSON, NFC, and no value is empty or equal to its key. Evidence: command output.
- [ ] AC-6 `npm run verify` passes; only the two allowed files changed.

## Edge cases
- Keys whose natural text is plural-sensitive: none carry a count in `contract-v1`, so avoid number-dependent wording ("1 recipient" versus "2 recipients"); phrase them without the count.
- A `{field}` value is the token `TO`, `CC` or `BCC`; write the text so that this token reads naturally in both languages.
- `error.*` and `import.error.*` texts are shown without any detail value; they must say what the user can do next, not only that something failed.

## Out of scope
- Any change to keys, parameters, code or tests; extra languages; marketing or user-guide text (AG-13).

## Evidence required
- Command output of `I18N_STRICT=1 npm run check:i18n` and `npm run verify`.
- The tables of AC-2 to AC-4 in the PR description.
