## Goal
The pure rule primitives behind recipient checking, recipient ordering and attachment-token checking exist, are correct on the plan's mandatory cases, and run in the JS-only runtime (no DOM, no Node APIs). After this card the real `sortRecipients` and `findShadowedPatterns` replace the stubs; the remaining `CoreApi` methods still come from the stub until CL-04 and CL-05.

## Design decisions (lead, reversible until Ready)
- **D1 Punycode:** hand-written RFC 3492 encoder (about 60 lines), no dependency, because `URL` and `domainToASCII` are unavailable in the JS-only runtime. Verified by a differential test against Node's `domainToASCII` (test environment only) and RFC 3492 vectors.
- **D2 Diacritics:** attachment-token matching always folds Vietnamese and other Latin diacritics (NFD, strip combining marks, `đ` to `d`). FR-4.5 calls it optional but `smr/1` has no field for it, and tokens are project codes, so always-on is the safe default. No schema change.
- **D3 Foreign-ring tokens:** tokens of expired rings (`expiresAt` in the past relative to a passed-in `now`) are ignored in the cross-ring check, so archived engagements do not produce false alarms. Time is a parameter; core never reads the clock.
- **D4 Scope boundary:** this card returns raw detections (who is outside the ring, which file lacks or carries a foreign token, which pattern is shadowed). Turning detections into `Finding`s with policy modes and messages is CL-05 (`policy`); `evaluate` orchestration is CL-05 and CL-08.

## Requirements
1. **`normalize`:** `normalizeAddress` (trim, NFC, lowercase local part and domain, domain to punycode label by label), `splitAddress` returning a `Result` (rejects no `@`, several `@`, empty parts, over 254 characters, labels over 63), `domainLabels` (right to left). Unresolved display-name-only entries yield an error, which callers treat as outside the ring (FR-1 edge case).
2. **`match`:** `matchMember(member, address)` and `findMatchingMember(members, address)` for kinds `address`, `domain`, `subdomains`. Exact domain does not match subdomains; `subdomains` (`*.abccorp.vn`) matches `mail.abccorp.vn` and `a.b.abccorp.vn` but not `abccorp.vn` and not `abccorp.vn.evil.com`; comparison is by whole labels from the right, never substring. `outsiders(ring, entries, ctx)` returns the recipients not matched, honouring `ring.internalDomain` (`allow | warn | outsider`) with the sender domain supplied in `ctx`.
3. **`order`:** pattern grammar for order lists: address, domain, `*.domain`, and `*` (the "rest" group). `rankRecipient` = index of the first matching pattern; no match ranks after everything and keeps original order (stable); `*` sets the position of the rest group (FR-3.3). `sortField(patterns, entries)` and `sortRecipients(ring, snapshot)` (sorting happens inside each field only; nothing moves between To, CC and BCC). `findShadowedPatterns(patterns)` per FR-3.4: a later pattern is shadowed when every address it matches is already matched by an earlier one (identical pattern, address under an earlier domain or `*.domain`, domain under an earlier `*.parent`, anything after `*`).
4. **Invariant (FR-3.6):** `sameRecipients(before, after)` compares the multiset of address, display name and field. `sortRecipients` returns `[]` and does not propose mutations when the invariant would be violated; `sortRecipientsChecked` returns the reason for logging by CL-08.
5. **`attachments`:** `tokenMatches(token, fileName)` boundary-aware: boundary is string start or end, or any character that is not a Unicode letter or digit; case-insensitive; NFC then diacritic folding (D2). `checkAttachments(ring, otherRings, attachments, now)` returns, per file, `ok | missingToken | foreignRingToken`. Inline files are skipped when `ignoreInline`; exempt extensions skipped; `item` attachments are checked by name (subject) and `cloud` by name; contents are never read. A file with a token of another ring and none of the current ring is `foreignRingToken` (highest severity signal, FR-4.3); tokens shared with the current ring are not foreign.
6. **`createCore`:** returns a `CoreApi` using real `sortRecipients` and `findShadowedPatterns`, delegating the rest to the fallback; `src/shared/contracts` exports `core`. Signatures are unchanged.
7. **Performance (NFR-1):** a test with 50 recipients, a 500-member ring and 20 attachments completes well inside 50 ms in CI (the 1.5 s budget is for the whole send check).

- [ ] AC-2 Punycode encoder equals Node `domainToASCII` on RFC 3492 vectors plus a fast-check property over random Unicode labels; `normalizeAddress` is idempotent (property).
- [ ] AC-3 Ordering properties (fast-check): sorting preserves the recipient multiset, is stable for unmatched recipients, is idempotent, and never moves a recipient to another field.
- [ ] AC-4 `findShadowedPatterns` returns exactly the expected pairs for a table of cases (address under domain, domain under `*.parent`, duplicate, after `*`) and no false positives for reversed order.

## Edge cases
- Uppercase domains, trailing dots, surrounding whitespace, `+tag` local parts (kept as given, only lowercased), unresolved recipients with empty address.
- Members with `kind: subdomains` whose base is a public suffix-like value (`vn`) are accepted as data; policy about them is the editor's concern (AG-03), not core.
- Order lists that mention an address not in the ring, and empty order lists (no reordering, original order kept).
- Several recipients with the same address in one field (multiset keeps duplicates).
