## Goal
Let Claude hand a bounded read-only brief to Antigravity without blocking on an MCP call and without tuning an idle timeout. Claude writes a job file, starts the runner as a background shell command, and is woken when it exits (done, failed, quota, timeout, cancelled). While it runs, a status command shows whether agy is alive. A run that stops answering is killed by the runner and its partial text is kept.

## Findings that shaped the design (2026-11-05, PO machine)
- `agy -p` with `--output-format stream-json` works over plain pipes: no PTY, no Python. Events: `init`, `step_update` (state ACTIVE/DONE, `step_type`, `text_delta`), and a final `result` (`status`, `response`, `conversation_id`). Text mode prints nothing until the turn ends, which is why the bridge's idle timer fired.
- agy honours the process `cwd`. Through the MCP bridge its `cwd` was the repo root even with no workspace, because the bridge never sets it. The runner sets `cwd` to the first added directory, or to an empty scratch directory.
- Headless agy cannot answer permission prompts. A prompt that makes it try a command stalls or ends the run, so the runner appends a standing "no command execution" constraint to every prompt.

## Requirements
1. `node scripts/agy-job.mjs run <id>` runs `.tools/agy-jobs/<id>/job.json` (`prompt`, `add_dir`, `workspace`, `model`, `idleSeconds`, `hardSeconds`) and exits with a code that tells the outcome: 0 done, 10 idle timeout, 11 hard timeout, 12 quota, 13 error, 14 denied by the guard, 15 cancelled.
2. Before starting agy, the runner applies `evaluate()` to the job exactly as for an `agy_ask` call. A denied job never starts agy.
3. agy runs with `cwd` ≠ repo root. Prompt length is capped; ids are validated so a job cannot leave `.tools/agy-jobs/`.
4. Every event is appended to `events.ndjson`; `status.json` holds state, pids, step count, conversation id and last-activity time; `result.md` holds the answer, or the partial text after a timeout.
5. Liveness: any stdout or stderr output resets the idle clock. No output for `idleSeconds` kills the process tree (`stalled → idle-timeout`, partial text kept, conversation id recorded for resume). A hard limit bounds the whole run.
6. `status <id>` reports `running`, `stalled` (quiet for more than half the idle limit), `finished` or `dead` (worker gone while the job says running), with worker and agy liveness and seconds since the last event. `cancel <id>` stops a run; `result <id>` prints the answer.
7. The PreToolUse hook also covers `Bash` and `PowerShell`: a shell command may start agy only through `node scripts/agy-job.mjs <run|status|result|cancel> <id>` (plus `agy --version` and `agy models`). This is a heuristic, not a sandbox.
8. `CLAUDE.md` documents the async path, the brief rules, and the quota and timeout handling of D-4 for it.

## Edge cases
- The shell heuristic can reject an unrelated command that has `agy` as its first word on any line (for example inside a heredoc). Write such text with the file tools instead.
- A job that is `running` in `status.json` but whose worker was killed (for example the machine slept and the session ended) is reported `dead`; `cancel` then kills any orphaned agy process.
- Quota is inferred only on a failed run, as in the bridge, so an answer that merely discusses HTTP 429 is not misread.
- The MCP path (`agy_ask`) stays for short calls. It is still bound by `AGY_BRIDGE_IDLE_TIMEOUT` (default 120 s) and `AGY_BRIDGE_TIMEOUT` (900 s), settable in the `env` of `.mcp.json`.
