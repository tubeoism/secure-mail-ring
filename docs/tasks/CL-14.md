## Goal
Antigravity can write component tests that render the real screens, click and type through real controls, and fail when the behaviour breaks. QA round 2 of PR #37 (AG-01B) showed that the repository cannot do this today: there is no DOM environment and no Testing Library, so the only possible tests are `renderToStaticMarkup` snapshots and tests of pure handlers, and 15 tests stayed green under five behavioural mutations. `AGENTS.md` §6.6 is not satisfiable without this card.

## Allowed paths
Lead-owned paths only: `package.json`, the lockfile, `vitest.config.ts`, `tsconfig.json`, `eslint.config.js`, `src/test-setup/**` (new, setup file only), `AGENTS.md` §6.6 wording if the PO asks, `docs/tasks/**`.

Antigravity-owned `src/taskpane/**` is not touched. Rewriting the AG-01B tests is Antigravity's work in AG-01B round 3.

## Scope
1. **New devDependencies** (this card is the explicit permission that `AGENTS.md` §6.3 asks for; nothing goes into the production bundle):

   | Package | Why | Notes |
   |---|---|---|
   | `jsdom` | DOM for Vitest | Pinned to one major; no browser download |
   | `@testing-library/react` | `render`, `screen`, `within`; React 18 | Peer: `@testing-library/dom` (installed by the package) |
   | `@testing-library/user-event` | Real click, Tab, Enter, Space, Esc sequences | v14 API (`userEvent.setup()`) |

   `@testing-library/jest-dom` is **not** added: assertions use plain `expect` on roles, names and `toBeTruthy`/`toBe`, so there is one dependency less to review.
2. **Vitest environment per folder, not global.** Core tests stay in `node`. Component tests (`src/**/*.test.tsx`) run in `jsdom` through `environmentMatchGlobs` or a per-project config. Stryker keeps mutating `packages/core` only and must still pass its dry run in under the current time.
3. **Setup file** `src/test-setup/dom.ts` (loaded only for the jsdom tests): clean up after each test, define `matchMedia`, `ResizeObserver` and `scrollIntoView` stubs that Fluent UI v9 needs, and fail a test on any `console.error` (React act warnings and missing-key warnings are real defects).
4. **Provider helper** `src/test-setup/renderApp.tsx`: renders `<App />` inside the Fluent provider with `MockOfficeAdapter` and the in-memory `StorageAdapter`, with the screen and language set the way `index.tsx` does. One entry point so every card tests the same wiring.
5. **ESLint**: the test files may import `@testing-library/*`; the rule that forbids `Office.*`, `localStorage` and `innerHTML` stays on for tests too.
6. **Worked example**: one test file `src/test-setup/example.test.tsx` that renders `App`, switches the language with the real control, opens the editor from the ring list with a click and closes it with Esc. It documents the pattern and proves the setup. AG-01B round 3 replaces the fake tests with real ones of the same shape.
7. **Mutation proof in the PR**: the three mutations that QA round 2 found surviving (remove `onNavigate("editor")` in `RingsScreen`, remove the container `onKeyDown` in `ShareScreen`, change the remainder `- 50` to `- 51` in `RingEditorScreen`) are applied by hand to the PR's example test target where possible, or described with the failing test name, so the tooling is shown to detect them. Any mutation the example cannot reach is listed for AG-01B round 3.

## Acceptance criteria
- [ ] AC-1 `npm ci` then `npm run verify` pass; no change in the number or result of the existing `packages/core` tests.
- [ ] AC-2 `git diff package.json` adds exactly the three packages above under `devDependencies`; the production bundle size and its dependency list are unchanged (`npm run build` output compared).
- [ ] AC-3 The example test renders `App`, clicks, presses Tab and Esc through `userEvent`, and fails when `onNavigate` or the `onKeyDown` it relies on is removed (failing output pasted in the PR).
- [ ] AC-4 A test that logs `console.error` fails.
- [ ] AC-5 The Stryker dry run on `packages/core` passes and its duration is within 20 % of the last run on `main`.
- [ ] AC-6 `scripts/path-guard.mjs` is unchanged and still blocks an `ag/*` PR that touches `package.json`, the lockfile or `vitest.config.ts`.
- [ ] AC-7 `npm audit --omit=dev` is not worse than on `main`; `npm audit` for the three packages is reported in the PR.

## Edge cases
- Fluent UI portals (Dialog, Menu, Tooltip) render outside the container: the helper exposes `screen`, not only the container queries.
- Fake timers and `userEvent`: the setup uses `userEvent.setup({ advanceTimers })` only where a test opts in; the default is real timers.
- jsdom has no layout: a 320 px overflow check cannot be a unit test. It stays a measured browser check with its script in `docs/tasks/evidence/` (AG-01B minor).

## Out of scope
- Playwright or any real-browser test runner in CI (a separate decision if the PO wants it).
- `@testing-library/jest-dom`, MSW, `happy-dom`.
- Rewriting the AG-01B tests (Antigravity, round 3 of PR #37).
- Any change to `src/taskpane/**`.

## Evidence required
- Tests: `src/test-setup/example.test.tsx`; the failing output of AC-3 and AC-4.
- Commands: `npm run verify`, `npm run test:mutation` timing, `npm audit` summary, `npm run build` size comparison.
