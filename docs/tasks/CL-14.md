## Goal
Antigravity can write component tests that render the real screens, click and type through real controls, and fail when the behaviour breaks. QA round 2 of PR #37 (AG-01B) showed that the repository cannot do this today: there is no DOM environment and no Testing Library, so the only possible tests are `renderToStaticMarkup` snapshots and tests of pure handlers, and 15 tests stayed green under five behavioural mutations. `AGENTS.md` §6.6 is not satisfiable without this card.

## Allowed paths
Lead-owned paths only: `package.json`, the lockfile, `vitest.config.ts`, `tsconfig.json`, `eslint.config.js`, `src/test-setup/**` (new, setup file only), `AGENTS.md` §6.6 wording if the PO asks, `docs/tasks/**`.

Antigravity-owned `src/taskpane/**` is not touched. Rewriting the AG-01B tests is Antigravity's work in AG-01B round 3.

## Scope
1. **New devDependencies** (this card is the explicit permission that `AGENTS.md` §6.3 asks for; nothing goes into the production bundle):

   | Package | Why | Notes |
   |---|---|---|
   | `jsdom` | DOM for Vitest | Pinned to one major; no browser download |
   | `@testing-library/react` | `render`, `screen`, `within`; React 18 | Peer: `@testing-library/dom` (installed by the package) |
   | `@testing-library/user-event` | Real click, Enter, Space, Esc sequences | v14 API (`userEvent.setup()`) |
   | `@testing-library/dom` | Peer dependency of `@testing-library/react` 16 (npm does not install it by itself) | Four packages, not three |

   `@testing-library/jest-dom` is **not** added: assertions use plain `expect` on roles, names and `toBeTruthy`/`toBe`, so there is one dependency less to review.
2. **Vitest environment per project, not global.** `vitest.config.ts` has two projects. `node`: everything that ran before, including the existing `renderToStaticMarkup` tests in `*.test.tsx`. `dom`: files named `*.dom.test.tsx` under `src`, in `jsdom` with the setup file. The suffix is the convention for Testing Library tests; `renderToStaticMarkup` tests warn under jsdom (`useLayoutEffect`) and stay in `node`. Stryker keeps mutating `packages/core` only and must still pass its dry run in under the current time.
3. **Setup file** `src/test-setup/dom.ts` (loaded only for the jsdom tests): clean up after each test, define `matchMedia`, `ResizeObserver` and `scrollIntoView` stubs that Fluent UI v9 needs, and fail a test on any `console.error` (React act warnings and missing-key warnings are real defects).
4. **Render helper** `src/test-setup/renderApp.tsx`: `renderApp({ screen? })` sets `?screen=` the way the dev server does, renders `<App />` (which owns the Fluent provider, `MockOfficeAdapter` and `MockStorageAdapter`) and returns Testing Library's result plus a `userEvent` instance. One entry point so every card tests the same wiring.
5. **ESLint**: the test files may import `@testing-library/*`; the rule that forbids `Office.*`, `localStorage` and `innerHTML` stays on for tests too.
6. **Worked example**: one test file `src/test-setup/example.dom.test.tsx` that renders `App`, switches the language with the real control and back, and opens the editor from the ring list with a click and with Enter on a focused ring. It documents the pattern and proves the setup. AG-01B round 3 replaces the fake tests with real ones of the same shape.
7. **Mutation proof in the PR**: two behaviours of `RingsScreen` (the click that navigates to the editor, the Enter/Space handler) and a `console.error` are broken by hand; the example test fails each time (output in the PR). The `Esc` and remainder mutations of QA round 2 need screens that exist only on the AG-01B branch; they are left for AG-01B round 3.

## Edge cases
- Fluent UI portals (Dialog, Menu, Tooltip) render outside the container: the helper exposes `screen`, not only the container queries.
- Fake timers and `userEvent`: the setup uses `userEvent.setup({ advanceTimers })` only where a test opts in; the default is real timers.
- **Tab order cannot be tested in jsdom with Fluent UI.** Fluent's Tabster handles Tab itself and treats every element as hidden (no layout), so focus falls to `<body>`. Tests set focus directly and press Enter, Space or Esc; the order of tab stops is checked in a real browser (Playwright script kept in `docs/tasks/evidence/`).
- jsdom has no layout: a 320 px overflow check cannot be a unit test. It stays a measured browser check with its script in `docs/tasks/evidence/` (AG-01B minor).
