## Goal
The free plan gives 2000 Actions minutes a month and 2104 were spent on 2026-11-05. About 95 % of that was the `mutation` job (Stryker, 13 to 46 minutes per run, growing with `packages/core`), run on every PR push and on every push to `main`, although Stryker only mutates `packages/core` and about 6 of 40 PRs that day touched it. Report: `/mnt/project-files/ci-minutes/actions-minutes-investigation-2026-11-05.md` (kept in the project files, not in the repository).

PO decision (2026-11-05, "Chạy tay"): mutation testing is not a CI job. It stays mandatory for core PRs, but it is started by hand.

## Allowed paths
Lead-owned: `.github/**`, `CLAUDE.md`, `docs/tasks/**`.

## Scope
1. `ci.yml` keeps only `verify` (lint, format, typecheck, tests, build, path guard, i18n).
2. New `mutation.yml`: trigger `workflow_dispatch` only, same steps as the old job, `timeout-minutes: 60`.
3. `CLAUDE.md` compensating controls: the mutation gate is run by hand on the final head of each PR touching `packages/core` or `src/launchevent`, and the score goes into the PR.
4. PR template: a checkbox for the manual mutation result on core PRs.

## How to run
- GitHub: Actions, workflow `Mutation`, Run workflow, choose the PR branch. About 25 to 45 minutes of runner time per run.
- Locally or in a Claude container: `npm run test:mutation`.
- One run per PR, on the final head, after the last change to `packages/core`. Not after docs-only pushes.

## Acceptance criteria
- [ ] AC-1 `ci.yml` has one job, `verify`; `git diff` shows the `mutation` job removed and nothing else changed in it.
- [ ] AC-2 `mutation.yml` parses and offers only `workflow_dispatch` (checked with `actionlint` or the Actions UI after merge).
- [ ] AC-3 `npm run verify` passes.
- [ ] AC-4 After the merge, a PR that touches only `docs/**` starts one job (`verify`) and no mutation job.
- [ ] AC-5 After the merge, `Mutation` can be started from the Actions tab on a branch and finishes with the Stryker score (PO or lead, once).

## Edge cases and risks
- The gate is no longer enforced by CI. A core PR can be merged without a score if the checkbox is ignored. QA (lead) refuses to give `QA: PASS` on a core PR without the score; the PO checks the box before merging.
- The repository is private on the free plan, so there is no branch protection that waits for a missing required check; nothing can hang.
- Cost of one manual run is the same as before (25 to 45 minutes); the saving comes from running it once per core PR instead of on every push and on `main`.

## Out of scope
Stryker incremental mode with a cache, path-filtered mutation in CI, `concurrency` for `verify` (verify is about 2 minutes per run). All three can be revisited if the PO wants the gate back in CI.

## Evidence required
- Diff of `ci.yml` and the new `mutation.yml`; `npm run verify` output.
