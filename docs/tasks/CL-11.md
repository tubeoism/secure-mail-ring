## Goal
Let a Claude Code session on the PO's Windows machine hand a bounded brief to Antigravity (`agy`) through a project-scoped MCP bridge, and read the result, without widening what Antigravity may see or write. The bridge is a transport for the existing card → branch → PR → QA flow. It does not replace that flow and does not change who owns which path.

## Requirements
1. **Routing table** in `CLAUDE.md` mapped onto the existing roles:

   | Task | Who | Rule |
   |---|---|---|
   | Architecture, contracts, core, send path, security, manifest | Claude | Never delegated |
   | QA of every `ag/*` PR | Claude | Always, per `qa-checklist.md` |
   | Implementation of a `Ready` AG card | Antigravity | Brief = the card; `add_dirs` = card's Allowed paths; Antigravity commits on `ag/*` |
   | Library/API research, option comparison | Antigravity (research mode) | No `add_dirs`, no repo content in the prompt |
   | Long-context analysis | Antigravity | Only allow-listed directories |
   | Design second opinion | Both, in sequence | Claude synthesises and records disagreements |

2. **Allow/deny lists** (enforced by a PreToolUse hook on `mcp__antigravity__*` that checks `cwd` and every `add_dirs` entry):

   | | Paths |
   |---|---|
   | Allow (write) | `src/taskpane/`, `src/readmode/ui/`, `src/shared/i18n/locales/`, `docs/user/`, `docs/rollout/`, `worker/heartbeat/` |
   | Allow (context, read) | `src/shared/contracts/`, `docs/tasks/<card>.md`, `docs/agents/qa-checklist.md` |
   | Deny | `packages/core/`, `src/launchevent/`, `src/shared/office/`, `src/shared/storage/`, `manifest/`, `build/`, `.github/`, `scripts/`, `spikes/`, `docs/spikes/`, `project_plan.md`, `.env*`, `node_modules/`, `dist/`, `coverage/`, `reports/`, `.stryker-tmp/`, `.git/`, `~/.gemini/` |

   The hook denies by default: any path not in an Allow row is rejected, and `cwd` must be an Allow (write) directory, never the repo root.

   **Core review exception (D-6).** `packages/core/` is accepted as `add_dirs` only for a call marked `mode: review`, whose `cwd` is a clean checkout of the PR head and whose brief is the PR description plus the diff. The prompt must say the review is read-only and advisory. The hook rejects `mode: review` combined with any write-allowed directory, and rejects `packages/core/` in any other mode. Before the first such call the PR head is checked with the post-build grep rules (no allowed domain, secret or source map; `AGENTS.md` §8), because the core is then sent to Google infrastructure.
3. **`.mcp.json`** registers the bridge for this project only (Windows: `py -3.11 -m agy_headless_bridge.mcp_server`, or the `agy-mcp-server` entry point from the project venv). The OAuth token under `~/.gemini/` is never read, copied or logged.
4. **2–3 Claude subagents** in `.claude/agents/`, each with a minimal tool set: a QA reviewer (applies `qa-checklist.md`, outputs the verdict line), a brief writer (turns a `Ready` card into a bridge brief), a decision logger (appends to the log below). Exact list is confirmed at sign-off.
5. **Decision log** `docs/agents/delegation-log.md`: one row per delegation (date, card, task type, worker, `add_dirs`, outcome).
6. **`AGENTS.md` updates**: §9 states that the bridge is a transport only and the card/PR/QA verdict remain the record; §10 states the bridge works only in sessions on the PO's machine, not in cloud sessions or CI.
7. **Path guard** treats `.mcp.json` and `.claude/**` as lead-owned.

## Edge cases
- `python` on PATH is 3.14; the bridge needs the interpreter named in `.mcp.json`, so `py -0` must show 3.11 before install. If it does not, stop and ask PO.
- The `claude` CLI is not on PATH in PowerShell, so `.mcp.json` is written by hand rather than with `claude mcp add`.
- Bridge defaults `cwd` for coding and has no directory for research; every call states `add_dirs` explicitly (empty for research).
- The bridge author states POSIX round trip is untested; AC-2 is therefore a hard gate on Windows, not an assumption.
- Antigravity running as an IDE on the same machine is not governed by these rules. Only bridge calls are.

## Out of scope
- Any change to feature cards, contracts or `packages/core`.
- Running several workers in parallel; CI integration; cloud sessions.
- Sending `packages/core` to Antigravity for anything other than the read-only advisory PR review in D-6.
